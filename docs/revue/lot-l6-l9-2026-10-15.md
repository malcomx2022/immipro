## L6 — recette navigateur des parcours authentifiés

La recette Python de S.178 (Chromium seul, à la main) devient une suite
Playwright de la porte commune : `npm run test:parcours`, six profils
Chromium/Firefox/WebKit × 390/1 440 px, vraie application, vrai worker,
PostgreSQL jetable `immipro_recette_parcours`, et les seuls fournisseurs
scriptés du banc `--parcours` (IA et checkout sur la boucle locale).
Un candidat synthétique par profil, créé par l'inscription réelle ; chaque
geste est contrôlé par son effet en base, jamais par un seul HTTP 200.

**Quinze scénarios par profil, en série :**

1. Simulateur au clavier, six réponses, recommandations calculées.
2. Inscription : téléphone normalisé en base, code capturé sur le SMTP
   local, vérification par Entrée, **état vide** du tableau de bord.
3. Ouverture : brouillon, règle figée, checklist persistée sans date.
4. Achat scripté : checkout intercepté, notification signée reçue par la
   vraie route, 30 analyses, rejeu sans double attribution (R-C02).
5. Consentement, téléversement réel, antivirus, lecture scriptée mesurée
   (120/30 jetons), débit.
6. **Coupure du stockage pendant l'envoi** : bandeau « Connexion perdue »,
   fichier gardé, relance automatique au retour sans nouvel appui, deux
   versions, historique (R-K01, R-C06).
7. **Réponse tardive** du fournisseur : version conservée, lecture publiée à
   l'arrivée, un seul débit (R-K06).
8. **Signalement** d'une erreur de lecture (sans débit), puis **B-05 au
   bureau** : motif, décision « Conforme », message contenant « visa
   garanti » refusé avec le bouton fermé, message reformulé accepté,
   pièce conforme, journal d'audit, message relu par le candidat
   (R-C05, R-C07, R-O01, R-O02, R-I04).
9. **Lecture sans mesure valide** (L2) : aucune publication, revue humaine
   ouverte, analyse non débitée, « Un opérateur regarde ta pièce » (R-K04).
10. Retrait du consentement : dépôt fermé, versions et quota inchangés.
11. **Rédaction assistée** : entretien, premier texte scripté débité puis
    soldé, version manuelle, export DOCX vérifié par requête authentifiée
    (archive ZIP, `Content-Disposition`), relecture débitée (R-C08).
12. **Deux onglets** : une seule relecture par version, « déjà en cours »,
    réservation retrouvée après actualisation, consultation sans second
    appel, un seul appel fournisseur (RG-08.10).
13. **Quota épuisé et reprise gratuite** sur un second dossier Essentiel :
    neuf lectures débitées, lecture illisible débitée puis rendue, reprise
    non débitée, dernière lecture débitée, « Tes 10 analyses du pack
    Essentiel sont utilisées », dépôt conservé sans analyse ; la limite
    d'appels de la route sensible est rencontrée et respectée (R-K05).
14. **Déclaration du dépôt** datée (date refusée hors bornes), conservation
    douze mois annoncée, dépôt refusé sur dossier figé, **clôture** avec
    issue, purge annoncée, archive consultable (R-C09, RG-10.8).
15. Bilan : aucun défilement horizontal sur les pages visitées du profil,
    aucune erreur JavaScript (R-I01), relevé JSON attaché.

Les écrans du back-office sont joués dans un contexte de 1 280 px quel
que soit le profil : ils restent conçus pour le bureau.

**Deux préconditions explicites**, limitées au candidat synthétique :
la lettre facultative de S.178, et un dossier marqué prêt (pièces
obligatoires conformes, `PRET` avec sa date) pour commencer la recette de
WF-10 là où WF-06 s'arrête. Elles sont nommées dans les preuves.

**Hydratation.** Sur les exécuteurs de la porte, plus lents, une touche
envoyée avant qu'React n'ait hydraté le formulaire déclenchait l'envoi
natif, sans redirection. La recette attend les clés React sur le nœud
visé avant chaque geste clavier, tolère les navigations de repli de Next et
reprend une saisie restée sans effet ; un code de vérification refusé passe
par « Renvoyer le code », qui annule le précédent, et c'est le dernier code
parti qui est saisi ; une bascule de consentement restée sans effet repart
d'une page rechargée ; chaque geste est borné à trente secondes. L'export
DOCX est vérifié par requête authentifiée plutôt que par l'événement de
téléchargement, absent sous Firefox en intégration continue.

**Montage.** Le relais HTTPS local de S.179 sert aussi le stockage
présigné (`--stockage-public https://localhost:3164`) : WebKit relève
sinon le PUT présigné vers https et aucun dépôt n'aboutit, alors que la
production sert le stockage en https. Le fournisseur scripté gagne un mode
`lente` (réponse tardive, double onglet). CSP de production intacte.

**Deux défauts réels reproduits par cette recette, corrigés avec test :**

- *L'éditeur ne suivait pas la version produite.* Après « Proposer un
  premier texte », la version arrivait dans la colonne des versions,
  débitée, mais « Ton texte » restait vide jusqu'à un rechargement
  complet (`Redaction.tsx`, état initialisé une fois). Le texte suit
  désormais la version courante quand elle change ; deux tests jsdom
  (`tests/ui/p1.test.tsx`) échouent sur l'ancien code. RG-08.4.
- *Le dénominateur du compteur comptait les rendus.* Après une lecture
  illisible débitée puis rendue, C-08 affichait « Analyses restantes : 1
  sur 11 » pour un pack de dix (`compteur()` sommait toute ligne
  positive). Le total ne compte plus que les octrois — achat, recharge,
  geste commercial ; `tests/compteur-du-quota.test.ts` échoue sur
  l'ancien code. RG-06.5, INV-6.

**Résultats.** 90 scénarios sur 90, six profils, 14,6 min sur la session de
développement (Chromium 156, Firefox 157, WebKit 27.2 — Playwright 1.64.1).
Par profil : 14 contrôles métier et 54 pages mesurées, aucun débordement
horizontal, aucune erreur JavaScript. WebKit relève à part 5 (390 px) et
17 (1 440 px) préchargements Next interrompus par la navigation suivante,
que Chromium et Firefox voient comme des requêtes annulées. Cycle
dépôt → antivirus → lecture scriptée : de 1,3 s à 4,6 s selon le profil ;
la limite d'appels de la route sensible a été rencontrée trois à quatre fois
par profil pendant l'épuisement du quota, toujours avec la saisie conservée.
[Relevés par profil](preuves-l6-2026-10-15/) ; rapport HTML, captures et
traces dans l'artefact CI `parcours-candidat`.

**Refaire la recette.**

```sh
npm ci && npx prisma generate && npm run build
# OpenSSL est requis pour les certificats locaux éphémères.
npx playwright install --with-deps chromium firefox webkit
# DATABASE_URL doit désigner un serveur PostgreSQL local de recette.
npm run test:parcours
# Un seul profil, ou un Chromium système :
npm run test:parcours -- --project=chromium-390
CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:parcours -- --project=chromium-1440
```

Le banc recrée `immipro_recette_parcours` sur ce serveur, puis ferme ses
processus. Les journaux `.recette/parcours-banc.log` et les courriers
capturés portent les mots de passe synthétiques : ils ne sont pas versionnés
et n'entrent pas dans l'artefact CI `parcours-candidat` (rapport HTML,
captures des échecs, traces et `preuves.json` par profil, sept jours).

**Ce que L6 garde ouvert.** Un lecteur d'écran humain et TalkBack ; les
pages juridiques absentes du banc ; la préproduction ; les gestes non
rejoués (changement de fuseau, pièce périmée, suppression de compte,
arbitrage B-02 à deux lecteurs, remboursement réel). La signature de la
matrice reste au responsable.
