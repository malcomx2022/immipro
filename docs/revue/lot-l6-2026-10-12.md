## Défaut reproduit puis corrigé

À 390 px, un numéro `00 229 01 97 00 00 42` saisi à l'inscription n'était
pas envoyé dans le POST et `User.phone` restait `NULL`. Quatre tests des
résultats attendus échouaient avant correction ; deux témoins passaient.

Le front envoie désormais `telephone: +2290197000042`. Même normalisation et
format international pour inscription/profil ; validation UI, API et service,
persistance sur le nouveau compte. Un numéro incomplet bloque l'envoi avec
l'aide sur l'indicatif. Le téléphone reste facultatif ; aucun indicatif n'est
deviné. Une inscription répétée conserve la réponse non énumérante et ne
modifie aucun compte. Pas de migration. WF-02 / RG-02.3.

DOC-11 décrit désormais le code email existant de six chiffres/dix minutes,
plutôt que le lien de 24 heures obsolète. Ce complément ne change pas la
politique de vérification de Claude Code.

## Recette reproductible

`npm run build`, puis sur un serveur PostgreSQL jetable :

```sh
npm run recette:banc -- --port 3160 --base immipro_recette_l6 --parcours
```

`DATABASE_URL` doit désigner ce serveur local. Le banc supprime/recrée
**uniquement la base indiquée**, qui doit commencer par `immipro_recette`.
Le mot de passe des comptes de démonstration et les codes restent dans son
journal local ; ne pas publier ce journal. Python Playwright installé séparément.

```sh
python scripts/recette/parcours-candidat.py \
  --base immipro_recette_l6 --banc-log /chemin/banc.log \
  --chromium /usr/bin/chromium --largeur 390 --sortie /chemin/mobile.json
# Même commande avec --largeur 1280 pour le bureau.
# --navigateur firefox ou webkit une fois leurs navigateurs installés.
```

La recette crée son propre candidat fictif. Lectures SQL en transaction
`READ ONLY`. Une précondition séparée ajoute une lettre **facultative
synthétique** seulement au dossier de ce candidat : la règle NL ne requiert
aucune lettre du catalogue. La préparation vérifie loopback, préfixe de base,
email `l6-…@immipro.test` et appartenance du dossier. Elle ne change aucun
référentiel et ne prouve pas qu'une destination exige cette lettre.

[Preuve Chromium 390 px](preuves-l6-2026-10-12/parcours-390.json) et
[preuve Chromium 1 280 px](preuves-l6-2026-10-12/parcours-1280.json) :
huit contrôles passent dans chaque largeur, sans erreur JavaScript détectée.
Avec vrais gestes et effets backend :

1. Six réponses au clavier et recommandations calculées.
2. Téléphone incomplet refusé, téléphone normalisé persisté, code SMTP capturé,
   vérification par Entrée et `emailVerified` enregistré.
3. Ouverture du dossier : état BROUILLON, règle figée, checklist créée,
   date inconnue conservée comme telle.
4. Checkout intercepté localement, webhook signé, transaction confirmée,
   30 analyses attribuées ; rejeu du même événement sans double attribution.
5. Consentement accordé, fichier déposé, scan SAINE, lecture synthétique
   120/30 jetons enregistrée et une analyse débitée. Le verdict A_CORRIGER
   vient des vérifications déterministes sur les champs synthétiques.
6. Autre fichier : deux versions et analyses persistées, historique ouvert,
   seconde analyse débitée.
7. Retrait du consentement, fichier sélectionné mais bouton de dépôt désactivé,
   nombre de versions et quota inchangés.
8. Lettre de recette : écriture manuelle, sauvegarde, téléchargement DOCX
   contenant une archive ZIP et relecture IA synthétique avec débit contrôlé.

Le faux compatible et Stripe n'utilisent que la boucle locale. Le préchargeur
est chargé **uniquement** par l'option `--parcours`, interdit les autres
origines et réécrit l'API Stripe vers le serveur local. Les réponses IA sont
scriptées, non évaluées pour leur qualité ; aucun appel Google, facturation
ou budget L5 utilisé. Le banc par défaut garde l'absence de fournisseur et
le chemin vers la revue humaine de S.170.

clavier automatisée ne certifie pas TalkBack ou un lecteur d'écran humain.
